# [제2장] 통합 요구사항 명세서 (Requirements & Specifications)

## 1. 기능적 요구사항 (Functional Requirements)

### FR-01. AI 평가 생성 시스템
*   **FR-01-1**: 사용자는 대상 학년과 주제 카테고리를 선택할 수 있어야 한다.
*   **FR-01-2**: 인퍼런스 결과로 반드시 제목, 지문, 최소 3개 이상의 다지선다형 문항이 JSON 형태로 반환되어야 한다.
*   **FR-01-3**: 지문 내에는 내용 이해를 돕는 시각적 도식(SVG 구조)이 혼합되어 있어야 한다.

### FR-02. 인터랙티브 학습 컨트롤(Take Test & Learning Tools)
*   **FR-02-1**: 지문을 문단 단위로 물리적 분할하여 보여주는 '학습 모드' 토글을 지원해야 한다.
*   **FR-02-2**: 모르는 단어를 마우스로 드래그 시, 단순히 사전적 의미가 아닌 "지문 내에서의 문맥적 의미"를 AI가 즉시 해석하여 플로팅 UI(팝업)로 제공해야 한다.
*   **FR-02-3**: 검색된 단어는 사용자의 Firestore 서브 컬렉션(Vocabulary List)에 버튼 클릭 1회로 비동기 저장되어야 한다.

### FR-03. 동적 마크다운/SVG 렌더링 무결성 (핵심 NFR 승격)
*   **FR-03-1**: AI 모델이 표기법을 어겨 `<svg>`를 코드블록 밖으로 누출시키거나 불완전한 태그를 생성해도, 페이지가 크래시되지 않고 SVG 이미지를 화면에 렌더링해야 한다.
*   **FR-03-2**: 선택지(Options) 내에 렌더링되는 인라인 SVG들은 찌그러지지 않고 모바일 뷰에서도 비율을 유지해야 한다.

## 2. 비기능적 요구사항 (Non-Functional Requirements)

### NFR-01. 응답성(Latency) 및 피드백 시각화
*   대량의 프롬프트 호출 구동 시 UI가 '얼어붙는' 현상을 방지해야 하며, 반드시 지연 상태를 Skeleton이나 Spinner 형태로 시각화해야 한다.

### NFR-02. 시스템 안정성 및 격리성
*   **컴포넌트 독립성**: 특정 문단 요약 기능 및 채팅 컴포넌트 내에서의 텍스트 인력 이벤트가, 전체 앱(DOM tree)을 불필요하게 리렌더링(State Bleeding) 시켜서는 안 된다.
