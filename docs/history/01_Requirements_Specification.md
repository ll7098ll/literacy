# [Phase 1] 극대화된 요구사항 명세서 (Exhaustive Requirements Specification)

## 1. 개요
*   **작성 목적**: 시스템이 완수해야 하는 모든 역할, 제약 사항, 엣지 케이스를 마이크로 단위로 세분화하여 나열합니다. 

## 2. 기능적 요구사항 (Functional Requirements, FR)

### FR-01: AI 테스트 시뮬레이션 및 평가 생성 엔진
*   **FR-01-A (동적 생성)**: 시스템은 학년(Grade)과 카테고리(Category) 정보를 입력받아 `services/geminiService.ts`의 `generateTestSet`을 호출하여 1개의 지문과 N개의 문항을 생성해야 한다.
*   **FR-01-B (어휘장 통신)**: 지문 생성 시, 단순히 글만 제공하는 것이 아니라 지문에 쓰인 핵심 어휘 중 사전에 학습된(저장된) 사용자의 Vocabulary Level을 참조하여 텍스트 난이도를 조정할 수 있어야 한다(향후 확장성 고려).
*   **FR-01-C (서식 완전성)**: 평가 지문에는 단순 텍스트뿐만 아니라, ````xml <svg></svg> ```` 기반의 도식 또는 차트 데이터를 요구할 수 있다.

### FR-02: 실시간 인지 및 상호작용적 학습(Interactive Learning)
*   **FR-02-A (문단별 가이드)**: 사용자가 지문을 읽는 동안 각 문단별로 '핵심 내용'을 입력할 수 있는 필드가 제공되어야 한다. (`TakeTest.tsx`)
*   **FR-02-B (AI 문단 피드백)**: 사용자가 입력한 문단별 추론을 즉시 평가하여 `generateParagraphFeedback`을 통해 실시간 스트리밍으로 피드백을 제공해야 한다.
*   **FR-02-C (사전 검색 - Contextual Dict)**: 지문 안의 난해한 어휘를 드래그/클릭하여 검색 시, 일반 사전적 의미가 아닌 **해당 지문의 문맥에 맞는 풀이**(`explainWordInContext`)를 반환해야 한다. 단어는 단어장(VocabularyList)에 저장할 수 있다.

### FR-03: 평가 결과 분석 및 리뷰 (Post-Test Review)
*   **FR-03-A (채점 시스템)**: 사용자의 오답/정답 데이터를 수집하고 총점을 산출해야 한다.
*   **FR-03-B (문항별 인터랙티브 해설)**: `ReviewTest.tsx` 라우트에서 틀린 문제에 대한 해설을 보여주는 동시에, "왜 틀렸을까?" 에 대한 꼬리 질문(AI Tutor Chat: `askAITutor`)이 가능해야 한다.

### FR-04: 무결점 마크다운 & SVG 렌더링 (Markdown & SVG Resilience)
*   **FR-04-A (형태 인지)**: AI가 응답한 마크다운의 형태가 인라인 코드 단위( `` ` ` `` )이거나 블록( ` ``` ` )이거나, 날것의 태그(` <svg> `)이더라도 엔진은 이를 파악해야 한다.
*   **FR-04-B (CSS 스케일링)**: 인라인 SVG는 문맥 내에서 알맞은 크기(`max-width: 400px; width: 100%`)로 렌더링되어야 하며, 블록 SVG는 전체 폭을 차지해야 한다. 어떤 상황에서도 `0x0px`로 축소되어서는 안 된다.

## 3. 비기능적 요구사항 (Non-Functional Requirements, NFR)

### NFR-01: 성능(Performance) 및 지연 시간(Latency)
*   **NFR-01-A (최초 응답 반응성)**: AI에게 긴 지문 기반의 요청을 보냈을 때 로딩이 길어지더라도, UI 상에서는 스켈레톤, 스피너 등을 통해 시스템 멈춤 상태가 아님을 시각적으로 1초 이내에 사용자에게 고지해야 한다.

### NFR-02: 안정성 및 오류 복구 (Reliability & Recovery)
*   **NFR-02-A (포맷 오류 방어)**: AI가 JSON 응답 규격을 어겼을 경우(예: 시작, 끝 브라켓 누락, 불필요한 줄바꿈 삽입), 시스템은 500에러를 띄우지 않고, 정규식을 사용해 JSON 포맷만을 추출해내는 내부 Fallback 모듈을 가동해야 한다.

### NFR-03: 상태 의존성 격리 (State Independence)
*   **NFR-03-A**: 각 컴포넌트는 전역 상태(Context)를 남용하기보단 Props 기반 순수 함수 형태로 데이터를 내려받아야 한다.
*   **NFR-03-B**: Firebase 세션 에러가 발생해도, 이미 불러온 로컬 메모리 상의 테스트는 중지되지 않고 지속 가능해야 한다.
