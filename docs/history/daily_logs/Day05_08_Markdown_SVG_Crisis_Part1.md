# [Hyper-Waterfall Daily Log] Day 05-08: [마크다운 대전쟁 제1막] SVG 렌더링 붕괴 대동란

## 1. 개요
*   **일자**: Day 05 ~ Day 08
*   **주요 목표**: AI가 지문 내부에 생성해낸 다이어그램, 벤다이어그램, 막대그래프 등의 SVG를 화면(React DOM)에 정상적으로 렌더링하기.
*   **결과**: 실패의 연속, 그리고 React Markdown 엔진의 심해 분석.

## 2. 발생한 현상 및 로그
*   사용자가 "표, 그림, 그래프, 도식 이런게 진짜로 SVG로 만들어져야해. 안 나와" 라며 크리티컬 핫라인 가동.
*   **초기 문제 분석**: AI는 시킨대로 매우 아름답고 완벽한 `<svg>` 코드를 텍스트 응답 안에 섞어 보냈다. 그러나, `react-markdown` 라이브러거 그걸 해석할 때 단순히 문자열이나 무시해야 할 블록으로 취급해버려 화면이 새하얗게 비어버리는 현상(Blank Issue) 발견.

## 3. 원인 파악 및 조치 1차 시도 (실패)
*   **조치**: `react-markdown`에 `rehype-raw` 플러그인을 주입. "원시 HTML 태그가 오더라도 당황하지 말고 그려라" 라고 시스템에 지시.
*   **결과**: **최악의 시스템 대붕괴**. `rehype-raw` 로 인해 허용된 `<svg>` 내부에는 `stroke-width`, `font-size` 같은 하이픈(-) 문법이 존재. React JSX 엔진은 이를 camelCase(예: `strokeWidth`) 가 아니라며 DOM 주입을 강제로 막음. 
*   콘솔창은 에러의 바다(Sea of Errors)가 되었고 화면 구성 자체가 마비됨.

## 4. 2차 시도 (격리형 패치 도입)
*   **아키텍처 변경**: SVG를 JSX 구문 안에서 컴포넌트로 풀지 않고, 철저히 `dangerouslySetInnerHTML` 내부에 숨겨 XSS 공격 방어 패턴과 유사하게 격리(Sandbox) 렌더링 방식을 시도하기로 결정. 후속 로직 개발(Day 9)로 이월.
